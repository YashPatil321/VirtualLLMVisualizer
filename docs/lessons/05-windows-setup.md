# Lesson 5: From nothing to an open project on Windows

[← Lesson 4](04-project-hygiene.md) · [Index](README.md) · Next: [Connecting an AI agent to the Unity editor →](06-connecting-ai-to-unity.md)

**You'll learn:** how to install Unity for Meta Quest development, create a project in
a way that keeps your repo intact, and get past the setup traps this project hit, in
the order they came up.

**Needs:** a Windows PC, about 20 GB of free disk, and an hour. Much of that hour is
waiting for downloads.

Throughout, replace `<you>` with your Windows user name.

---

## Step 1: Skip the welcome tutorial

Unity Hub opens on a **Get set up** screen with a big **Start project** button under
"Complete in-Editor tutorial".

**Don't click it.** It creates a tutorial project on the Built In Render Pipeline,
which this project can't use, and which the Hub's own banner says is being deprecated.

## Step 2: Check the Android module

Click **Installs**. Under your Unity version you'll see small badges for the platforms
it can build for.

<details>
<summary><b>Predict first:</b> the badges say <b>Web</b> and <b>Windows</b>. Can you build to a Quest?</summary>

No. The Quest runs Android, so you need the Android badge. Without it, Android doesn't
even appear in Build Settings, and nothing tells you why.

</details>

To add it: **Manage → Add modules** → tick **Android Build Support**, then expand it
and also tick **Android SDK & NDK Tools** and **OpenJDK**. Those two nested items are
easy to miss, and you need both.

When it's done, the badges read **Android · Web · Windows**.

## Step 3: Decide the version now

This project ended up on **Unity 6.6 (6000.6.1f1)**. The constraints call for a
Unity 6 **LTS** (long term support) release, and the Hub's banner mentioned 6.7 LTS,
so 6.6 may not be one.

Check the **Official releases** tab for the version tagged LTS. Switching now costs a
download. Switching later means upgrading a project with scenes and baked lighting in
it. Whatever you choose, write it down (lesson 4) so everyone uses the same one.

## Step 4: Why you need a throwaway project

A Unity project folder needs three things:

```
Assets/           your code and content. This repo has it.
ProjectSettings/  generated by Unity. The repo doesn't have it at first.
Packages/         generated by Unity. The repo doesn't have it at first.
```

Only Unity can generate the last two, and it only does that when you create a new
project. But the Hub refuses to create a project in a folder that already has files in
it, so you can't point it at the repo.

The workaround: create a blank project, take the two folders Unity generated, and put
them in the repo. A script does the copying.

## Step 5: Create the throwaway project

**Projects → New project**, then:

| Field | Choose | Why |
|---|---|---|
| Template | **Universal 3D** | URP. Not "3D" or "3D Core", which are Built In RP |
| Project name | anything, e.g. `OCSVisualizer-fresh` | You'll delete it |
| Name dropdown | **Create new local project** (monitor icon) | The cloud option links Unity Cloud services you don't need |
| Version control | **Select none** | You already have git. Unity's options would set up a second, competing system |
| Use AI Assistant | leave ticked | See the note below |
| Use Unity CLI | leave ticked | Installs the `unity` command |

If the Universal 3D template shows a download icon, click it first.

Let it open fully (the first launch compiles shaders and is slow), then quit Unity.

> **Where it went wrong**
>
> Ticking "Use AI Assistant" was expected to install Unity's AI Assistant package,
> which is what Unity's MCP server lives in. It didn't. The package wasn't in the
> generated manifest, and there was no AI section in Project Settings afterwards.
> Lesson 6 covers what to do instead.

## Step 6: Clone and merge, from a normal PowerShell

Open **Windows PowerShell** from the Start menu. **Not as Administrator.** More on why
in step 9.

Check git first:

```powershell
git --version
```

If it isn't recognised, install [Git for Windows](https://git-scm.com/download/win),
then close and reopen PowerShell. Then:

```powershell
cd $HOME
git clone -b claude/nifty-cannon-b34hkf https://github.com/YashPatil321/VirtualLLMVisualizer
cd VirtualLLMVisualizer
.\tools\bootstrap-unity-project.ps1 -Fresh "$HOME\OCSVisualizer-fresh"
```

Adjust the `-Fresh` path to wherever the Hub put your throwaway project. If PowerShell
says running scripts is disabled, this allows just this one script:

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\bootstrap-unity-project.ps1 -Fresh "$HOME\OCSVisualizer-fresh"
```

Success looks like:

```
Copying the generated project config into the repo...

Checking every asset still has its .meta ...
  all good
```

## Step 7: Open the repo, not the throwaway

Back in the Hub, the **Projects** list may be empty even though you just created a
project. That's fine.

Click **Add ▾ → Add project from disk** and pick:

```
C:\Users\<you>\VirtualLLMVisualizer
```

Pick the folder itself. Don't go inside it. If the file picker is awkward, paste the
path into its address box.

The first open takes several minutes while Unity builds its `Library/` cache and
compiles everything. Don't kill it.

When it's up, open the Console (**Window → General → Console**). Red errors need fixing
before anything else. A C# compile error puts the editor in Safe Mode, where packages
don't load and nothing else in lesson 6 will work.

## Step 8: Package Manager has two views

**Window → Package Manager**. The left side has two groups:

- **Project → All Packages**: what's already installed
- **Sources → Unity Registry**: everything you could install

<details>
<summary><b>Predict first:</b> you search "OpenXR Plugin" while "All Packages" under Project is selected, and get no results. Is OpenXR unavailable?</summary>

No. You're searching only what's installed. Click **Unity Registry** under Sources and
search again.

</details>

For an installed package, the details panel shows **Locate** and **Manage** buttons.
For one that isn't installed, it shows **Install**. The Test Framework came
preinstalled.

You can skip the XR packages (OpenXR, XR Interaction Toolkit) until you have a headset.
They do nothing without one, and they can add warnings you can't act on yet.

## Step 9: "Detected dubious ownership"

When this project first tried to commit from Windows, git refused:

```
fatal: detected dubious ownership in repository at 'C:/Users/<you>/VirtualLLMVisualizer'
'C:/Users/<you>/VirtualLLMVisualizer' is owned by:
        BUILTIN/Administrators
but the current user is:
        <PC>/<you>
```

The clone had been done from an **Administrator** PowerShell, so the folder belonged to
the Administrators group. Later, a normal PowerShell ran as the ordinary user, and git
refused to trust a repo owned by someone else.

Git prints the fix. Copy it exactly, with forward slashes:

```powershell
git config --global --add safe.directory C:/Users/<you>/VirtualLLMVisualizer
```

This is safe here. The check exists to stop you running hooks or config from a repo
that belongs to another person. In this case, the "other person" is you with
elevation, in your own home folder. The lasting lesson: **don't use Administrator
PowerShell for development work.** You don't need it.

## Step 10: Commit what Unity generated

```powershell
git status
git add ProjectSettings Packages
git commit -m "Add Unity project settings and packages"
git pull
git push
```

Look at `git status` before adding. If Unity created assets under `Assets/`, like URP
settings or a scene, add those with their `.meta` files too. This project missed them
the first time (lesson 4).

The first push from a new machine opens a browser to sign in to GitHub.

## Troubleshooting

| You see | Likely cause |
|---|---|
| No Android option in Build Settings | Android module missing, or its SDK/NDK and OpenJDK sub-items weren't ticked |
| Bootstrap script: "No ProjectSettings in ..." | The `-Fresh` path points somewhere other than the throwaway project |
| Bootstrap script: "running scripts is disabled" | Use the `-ExecutionPolicy Bypass` form |
| Hub's Projects list is empty | Normal. Use Add → Add project from disk |
| Package search finds nothing | You're searching installed packages. Switch to Unity Registry |
| git: dubious ownership | The folder was created from an Administrator shell. Use `safe.directory` |
| Every editor command fails, oddly | A compile error put the editor in Safe Mode. Fix the Console errors first |
